# サーバーレスAPIのデータ整合性・運用チェックリスト

[`serverless-api-hardening-checklist.md`](serverless-api-hardening-checklist.md)の続きである。Lambda + API Gateway + DynamoDB構成の棚卸しで繰り返し見つかった観点をまとめる。各観点に確認方法を1文で添える。

## 1. 認可と同時更新

| 観点 | 内容と確認方法 |
|---|---|
| 認可（認証済み＝全権になっていないか） | ログインの許可制とは別に、共有データの書き込みを誰に許すかを確認する。書き込み系のルートごとに所有者・役割の検査があるかを見る |
| 同時更新での上書き | 「読む→一部を変える→全体を`Put`」は、同時操作で互いの変更を消す。属性単位の`UpdateCommand`と`ConditionExpression`を使う。`get`の直後の`put`を探す |
| 副作用を伴う書き込みの冪等性 | 再送・二重タップで同じリクエストが複数回届く。条件付き書き込みより前に別の書き込み（加算等）が無いかを見る。複数の書き込みは`TransactWriteItems`で1回にまとめる |
| クライアント申告値の検証 | サーバーで再計算できる値（合計・勝敗等）を申告のまま保存していないか。再計算して一致を確認する |
| 公開されたままの未使用エンドポイント | `serverless.yml`の`http`イベントと、フロントエンドの呼び出し箇所を突き合わせる |

## 2. 親子レコードと複数書き込み

| 観点 | 内容と確認方法 |
|---|---|
| 親削除時の子レコード | 削除の順序は「子→親」にする（途中で失敗しても、親が残ればやり直せる）。親だけを消して子が残っていないかを見る |
| 複数書き込みの途中失敗 | 「作成＋初期データ投入」が途中で失敗しても、中途半端な状態が残らないか。補償処理（作成済みの削除）の有無を見る |
| メンバーの退出・除外 | 招待で参加者を増やせるなら、外す手段があるか。外した相手を指す参照（担当者等）の後始末も見る |

多数の項目を書き込む・取得するときは、`shared/lambda/dynamoBatch.js`を使う。

## 3. 読み取りの設計とGSI

| 観点 | 内容と確認方法 |
|---|---|
| 全利用者分を読んでメモリ上で絞り込んでいないか | 1MBに達していなくても、利用者数に比例して遅く・高くなる。GSIによる`Query`へ置き換える。`Scan`の使用箇所を探す |
| GSI追加時の制約 | CloudFormationは1回の更新で、1テーブルにつきGSIを1つしか作成・削除できない。複数追加はデプロイを分ける。GSIは結果整合のため、書き込み直後の再取得に反映されないことがある |

## 4. エラー応答とログ

| 観点 | 内容と確認方法 |
|---|---|
| 500応答の中身とログ | 想定外の例外の`message`を応答へ載せていないか。捕捉した時点でログへ出しているか。`catch`節を見る |
| 失敗を捕捉して200で縮退する処理 | DB読み取りの失敗時に初期データを返す等の縮退は、`Errors`でも5xxでも検知できない。縮退時は固定のマーカー付きでログへ出し、メトリクスフィルタでアラームにする。応答にも縮退中であることを含める |
| ログの保持期間 | Lambdaのロググループは既定で無期限に保持される。後から同名の`AWS::Logs::LogGroup`を定義すると、自動作成済みのものと衝突してデプロイが失敗する。別名のロググループを関数側で指定する |

## 5. IAMとデプロイ

| 観点 | 内容と確認方法 |
|---|---|
| IAM権限と実際に使うAPIの不一致 | コードが使う`*Command`に対応するActionが実行ロールに無い状態。テストはDynamoDBをモックするため検知できない。`*Command`の使用箇所とIAMステートメントを突き合わせる。CIでは`enable_iam_actions_check`で検知できる（[`reusable-workflows-reference.md`](reusable-workflows-reference.md)参照） |
| デプロイパッケージの中身 | `package.patterns`未設定で、テストファイル・設定ファイルがzipに入っていないか。zipの中身を一覧する |
| CD内の補助スクリプトの失敗 | シード投入等が、失敗を握りつぶして終了コード0で終わっていないか。Lambda上で自動設定される`AWS_REGION`等が、CDのステップには無い点にも注意する |

## 実例

- Camp-Stock（`bamiyanapp/Camp-Stock`）の棚卸し（2026-11）。1〜4が該当した
- Electric-Chair-Arena（`bamiyanapp/Electric-Chair-Arena`）の棚卸し（2026-11）。1〜5が該当した。運用監視・エラー報告の導入が本番停止の原因にもなった（symlink共有したファイルがデプロイパッケージから欠落。#1386と同じ事象）
